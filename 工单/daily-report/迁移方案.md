## 二、迁移步骤

### 1. 新集群环境准备
```bash
# 新集群需要：kubectl + kubeconfig 已配置好
# 创建命名空间
kubectl create ns daily-report
```

### 2. 迁移 ConfigMap
```bash
# 导出
kubectl get cm daily-report-config -n daily-report -o yaml > configmap-backup.yaml
kubectl get cm mysql-init-sql -n daily-report -o yaml > mysql-init-sql-backup.yaml

# 导入到新集群（注意清理 metadata 中的 uid/resourceVersion/creationTimestamp）
kubectl apply -f configmap-backup.yaml
kubectl apply -f mysql-init-sql-backup.yaml
```

### 3. 迁移 Secret
```bash
# 导出
kubectl get secret daily-report-secret -n daily-report -o yaml > secret-backup.yaml
kubectl get secret daily-report-tls -n daily-report -o yaml > tls-backup.yaml

# 导入到新集群
kubectl apply -f secret-backup.yaml
kubectl apply -f tls-backup.yaml
```

### 4. 迁移 MySQL 数据（最关键的一步）

```bash
# 4.1 在旧集群 master01 节点上打包数据
# SSH 到 k8s-master01，或在 master01 上执行：
tar czf /tmp/mysql-data.tar.gz -C /data/mysql .

# 4.2 拷贝到新集群节点（scp、U盘、内网传输等方式）
scp /tmp/mysql-data.tar.gz root@新节点IP:/data/

# 4.3 在新节点解压
mkdir -p /data/mysql
tar xzf /data/mysql-data.tar.gz -C /data/mysql
chown -R 999:999 /data/mysql   # MySQL 默认 uid:gid 是 999:999

# 注意：如果新集群是多节点，mysql pod 可能调度到非预期节点
# 建议用 nodeSelector 固定到某个节点
```

### 5. 部署 MySQL
```bash
# 直接用项目中的 yaml
kubectl apply -f k8s/mysql.yaml

# 检查 pod 是否起来，数据是否完整
kubectl get pod -n daily-report
kubectl exec -n daily-report mysql-0 -- mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SELECT count(*) FROM daily_report.engineers"
```

> 如果新集群没有 `110.42.231.162:5000/mysql:8.0` 这个镜像，改为官方镜像：
> 修改 mysql.yaml 中 `image: mysql:8.0`

### 6. 迁移容器镜像
```bash
# 方式 A：旧镜像仓库可达的话，yaml 不用改，直接部署
# 方式 B：旧仓库不可达，重新构建推送
cd C:\Users\2914\Desktop\工单\daily-report
docker build -t 新仓库地址/daily-report:latest .
docker push 新仓库地址/daily-report:latest
# 然后修改 k8s/app-deployment.yaml 中的 image 地址
```

### 7. 部署应用服务
```bash
kubectl apply -f k8s/app-deployment.yaml  # Deployment
kubectl apply -f k8s/configmap.yaml        # 如果还没创建
kubectl apply -f k8s/mysql.yaml            # 如果还没创建
kubectl apply -f k8s/ingress.yaml          # Ingress
```

### 8. 检查服务状态
```bash
kubectl rollout status deployment/daily-report-app -n daily-report
kubectl get pods -n daily-report
curl http://localhost:3000/health   # 从集群内测试
```

## 四、一键迁移脚本（在新集群 master 节点执行）

```bash
#!/bin/bash
NS="daily-report"

# 1. 创建命名空间
kubectl create ns $NS 2>/dev/null

# 2. 创建 ConfigMap 和 Secret（文件需提前拷贝到新节点）
kubectl apply -f configmap-backup.yaml
kubectl apply -f mysql-init-sql-backup.yaml
kubectl apply -f secret-backup.yaml
kubectl apply -f tls-backup.yaml

# 3. 创建 MySQL（假设 /data/mysql 已准备好数据）
kubectl apply -f mysql.yaml

# 4. 等待 MySQL 就绪
kubectl wait --for=condition=ready pod/mysql-0 -n $NS --timeout=120s

# 5. 部署应用
kubectl apply -f app-deployment.yaml
kubectl apply -f ingress.yaml

# 6. 等待应用就绪
kubectl rollout status deployment/daily-report-app -n $NS
```

## 五、回滚方案

如果新集群出问题：
1. 旧集群的所有资源还在，DNS 切回旧 IP 即可恢复
2. MySQL 数据在旧节点 `/data/mysql`，不会丢失
